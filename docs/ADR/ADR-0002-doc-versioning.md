# ADR-0002 · 文档版本链与变更规范

| 项 | 值 |
|---|---|
| **状态** | 已采纳（2026-09-10） |
| **影响文档** | [docs/README](../README.md)、[CHANGELOG](../CHANGELOG.md) |

## 背景

项目此前无产品设计文档，需求/功能变更无沉淀，设计决策靠 git 提交记录零散还原。用户要求"开启版本链管理，每次需求及功能变更应同步对应版本链文档"。

## 决策

建立版本链 = **文档版本头 + ADR + CHANGELOG 事件流**三者咬合：

1. 每篇设计文档带版本头（版本 / 更新时间 / ADR / 变更摘要）。
2. 每次需求/功能/架构变更**必须双写**：改对应文档（含版本头）→ `docs/CHANGELOG.md` 顶部追加一条。
3. 重要决策新建/更新 `docs/ADR/ADR-00NN-*.md`。
4. 文档版本用 SemVer 语义：major=架构级破坏 / minor=功能级 / patch=澄清。

## 后果

- 任何时刻可回答"这个设计为什么这样、何时变的、当时怎么决定"。
- 文档与代码双轨演进，CHANGELOG 建立代码版本 ↔ 文档版本对应。
- 强制规范：禁止"只改代码不改文档"。
